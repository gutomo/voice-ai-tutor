# 音声AI日本語チューター｜デモ設計書

**対象:** LPK（職業訓練機関／送り出し機関）向けB2B  
**デモシナリオ:** 介護「朝の声かけ＋バイタルチェック」  
**ターゲットレベル:** A2相当（N4手前からN4）／育成就労の特定技能移行要件N4を見据える  
**提供形態:** モバイルWeb録音（アプリ不要）＋結果メール。WhatsApp連携はPhase 2

---

## 0. このデモで証明すること（1枚要約）

育成就労制度では2027年4月から、就労開始前に日本語A1相当（N5等）の合格または認定機関での講習受講が**全候補者に必須**になる。LPKにとって日本語の合格率は事業の生命線になる。このデモは、その合格率を「アプリ不要のWeb録音」で底上げし、「教師が合格ラインをデータで可視化できる」ことを示す。

1回のデモで見せる3つの差別化:

1. **初級 × 現場特化**：既存の会話AI（HAi-J等）はN2前後狙いで、介護の現場日本語は手薄。ここをA2/N4 × 介護に振り切る。
2. **Web録音＋メール完結（アプリ不要）**：候補者の多くは低スペックAndroid。モバイルブラウザでタップ録音するだけで成立し、アプリのインストールもWhatsApp Business Account（WABA）の取得も不要。寮生活の合間に練習できる。
3. **発音から合格ライン予測まで出すB2Bダッシュボード**：既存アプリは全てB2C個人課金。教師が一覧で「誰が合格圏か」を見られるのは新しい。

**デモの山場（money shot）:** 候補者がWeb画面で音声を1本録る → 画面に発音スコアが即表示され、同時に教師ダッシュボードで「介護日本語評価試験 合格ライン到達度」が動く。

## 1. 対象シナリオ：介護「朝の声かけ＋バイタルチェック」

**なぜ介護か**
- 育成就労16分野で最大級の人材需要。あなたの介護・ヘルスケア領域の注力とも一致。
- 介護日本語評価試験という明確なKPIアンカーがあり、合格ライン予測に落としやすい。
- 現場で毎日繰り返す定型表現が多く、初級でも「使える日本語」を短時間で体感させやすい。

**学習目標（このレッスン1本）**
- 3つの定型表現を声に出して言える：朝の挨拶、体温の声かけ、血圧の声かけ。
- 利用者役の簡単な応答に対し、適切に返せる（理解 → 応答）。

**到達基準**
- 発音スコア（Accuracy）70点以上で「合格圏入口」、85点以上で「安定」。
- ロールプレイのタスク達成（声かけ → 測定の流れを最後まで成立）。

## 2. ユーザー体験フロー（Web録音・メール、アプリ不要）

候補者はモバイルブラウザでリンクを開くだけ。録音と即時フィードバックは画面上で完結し、レッスンのまとめと次回の宿題はメールで届く。説明はBahasa Indonesia、練習対象は日本語。以下は1レッスンの流れのサンプル。

**Step 1｜開始・簡易診断**
> 🤖（画面のテキスト＋音声、Bahasa）：「こんにちは！介護の日本語練習を始めましょう。まず、自己紹介を日本語で話してみてください（短くてOK）」  
> 👤（タップ録音）：学習者が自由に話す  
> → 内部で初期レベルを推定し、開始難易度を決める。

**Step 2｜レッスン導入**
> 🤖（Bahasaで説明 + 日本語モデル音声を再生）：「今日は朝の声かけを練習します。最初のフレーズです。私の後に言ってください」  
> 🔊 モデル音声：「おはようございます。体温を測りますね」

**Step 3｜復唱 → 発音採点 → フィードバック**
> 👤（タップ録音）：「おはようございます。たいおんを はかりますね」  
> 🤖（画面に即時フィードバック）：  
> 「発音 78点 👍 だいぶ伝わります。  
> ・『体温（たいおん）』はOK  
> ・『測ります（はかります）』の『か』がやや弱い。もう一度ゆっくり言ってみましょう  
> （Bahasaで補足）「か」は息を強めに、です」  
> 🔊 弱い音だけ抜き出したモデル音声を再生

ここで**わざと少し外した例**を見せると、音素レベルの指摘が刺さる。

**Step 4｜ロールプレイ（AIが利用者役）**
> 🤖（利用者役の音声）：「ああ、おはよう…なんだか今日は少し寒いねえ」  
> 👤（タップ録音）：「そうですね。寒いですね。窓を閉めましょうか」  
> 🤖（フィードバック）：  
> 「タスク達成 ✅ 自然な応答です。  
> 文法：◎／語彙：適切／敬語：丁寧で良い  
> 次の一言まで言えると満点：『毛布をもう1枚お持ちしますね』」

**Step 5｜まとめ・宿題・教師共有**
> 🤖（画面）：「今日のスコア：発音 78／会話 4.0（5点満点）。合格ライン到達度：介護日本語評価試験 推定 62%。明日は『お薬の声かけ』を練習しましょう。おつかれさまでした！」  
> 📧 同じ内容を学習者へメール送信（次回リンク付き）。あわせて結果が教師ダッシュボードへ自動連携。

## 3. 採点・レベル判定ロジック

3つの信号を合成して、学習者プロファイル（推定レベル＋合格ライン到達度）を出す。

| 信号 | 取得元 | 何を測るか | 使う場面 |
|---|---|---|---|
| (A) 発音スコア | Azure Speech 発音評価（ja-JP） | Accuracy / Fluency / Completeness（音素・単語レベル） | 復唱（scripted assessment） |
| (B) ルーブリック採点 | Bedrock Claude | 文法・語彙・タスク達成・敬語をCEFR記述子で0から5採点 | 自由応答・ロールプレイ |
| (C) タスク達成 | Claude（構造化判定） | シナリオのゴールを満たしたか（bool＋理由） | ロールプレイ全体 |

**合成の考え方（デモ用の簡易版）**
- 発音点（A）と会話点（B×20で100点換算）を重み付け平均し、タスク達成（C）でボーナス／減点。
- レッスン累積で推定CEFR（A1/A2/B1）と推定JLPTレベルを更新。
- 介護日本語評価試験／JFT-Basicの合格ライン到達度（%）を、過去問の難易度マッピングから推定して表示。

**Azure側の注意点（実装メモ）**
- 日本語の prosody 評価は未対応（prosody は en-US のみ）。ja-JP では Accuracy / Fluency / Completeness を主指標にする。
- unscripted（自由発話）採点のSTTは通常のAzure STTと別モデル。精度の高い参照テキストが要るときは、先にAzure STTで文字起こし → その文を参照にして scripted assessment、の二段で回すと安定する。
- 復唱ドリル（モデル文が既知）は scripted assessment が最も情報量が多い（音素レベルの弱点が取れる）。デモの山場はここで作る。

## 4. 教師ダッシュボード（B2Bの肝）

このダッシュボードがLPKに売る理由そのものになる。個人アプリには無い「クラスを管理し、合格率を担保する」機能。

**学習者ビュー**
- 推定レベル（CEFR / JLPT）と推移グラフ
- 発音ヒートマップ：苦手な音素（例：「つ」「りょ」など）を色で可視化
- 合格ライン到達度の推移（介護日本語評価試験／JFT-Basic）
- 会話ログ＋音声の再生（教師が抜き打ちでチェックできる）

**コホート（クラス）ビュー**
- クラス全体の合格見込み分布
- **要フォロー学習者を自動フラグ**（例：「2名が伸び悩み、発音が合格圏未満」）
- 出国予定日までの逆算アラート

**そのまま営業・制度対応に使える出力**
- 「当校はN4合格率◯◯%、データで担保します」という日本企業向け資料。
- 育成就労計画の「日本語到達目標」のエビデンスとしても転用可能。

## 5. 技術アーキテクチャ

### データフロー
```
[候補者のモバイルブラウザ（アプリ不要）]
   │ MediaRecorderで録音（WebM/Opus）→ POST
   ▼
[FastAPI オーケストレーター(Python)]
   │ ① ffmpegで WAV(16kHz, mono) に変換
   ▼
          ┌─────────────────────┬───────────────────────┐
          ▼                     ▼                       ▼
  [Azure Blob 一時保存]   [Azure Speech ja-JP]     [Bedrock Claude]
                          ・STT(文字起こし)          ・利用者役の会話生成
                          ・発音評価(音素レベル)      ・ルーブリック採点
                                │                  ・タスク達成判定
                                └──────────┬───────────┘
                                           ▼
                                  [スコア合成・レベル推定]
                                           │
                  ┌────────────────────────┼─────────────────────┐
                  ▼                        ▼                      ▼
         [Azure TTS ja-JP]         [PostgreSQL]            [React ダッシュボード]
         返信音声を生成              学習者プロファイル        教師用Web
                  │                        │
                  ▼                        ▼
   [ブラウザに即時表示・再生]      [メール: SES / SendGrid]
   ・スコア＋訂正＋次のターン      ・レッスンまとめ → 学習者
   ・返信音声を再生               ・クラス状況レポート → 教師
```

### 採用根拠

- **発音採点 = Azure Speech 一択**：ja-JPがGAで音素レベルまで取れる。あなたがAzureセールスである点と二重に噛み合い、そのまま顧客向けのAzureリファレンス実装になる（SoftwareOneの提案資産にも転用可）。
- **会話ブレイン = 既存のBedrock Claude流用**：日本語とBahasaの両対応、ルーブリック採点や構造化出力（JSON）に強い。完全Azure化したい場合はAzure OpenAIへ差し替え可能（アーキは変えずプロバイダだけ交換）。
- **TTS = Azure Neural TTS（ja-JP）でデモは1ベンダーに寄せる**。プロソディの自然さを上げたい本番フェーズで ElevenLabs を検討。
- **Web録音＋メールをMVP、WhatsApp/通話はPhase 2**：WhatsApp Cloud APIはBusiness Account（WABA）の取得とMetaの審査が必要なため、デモでは外す。モバイルブラウザのMediaRecorderならアプリ不要で当日から動き、低スペックAndroidも対応できる。リアルタイム通話（LiveKit/Twilio、歯科エージェントの足場）と、WABA取得後のWhatsApp連携は上位プランで後付けする。
- **ブラウザ音声の形式に注意**：MediaRecorderの既定はWebM/Opus（端末・ブラウザで差異あり）。Azureの発音評価へ渡す前に、サーバ側でffmpegを使いWAV(16kHz, 16bit, mono)へ変換するのが最も確実。
- **メール送信 = Amazon SES もしくは SendGrid**：レッスンまとめ（学習者向け、次回リンク付き）とクラス状況レポート（教師向け）に使用。会話の即時フィードバックはあくまで画面側で完結させ、メールは「まとめ」と「リマインド」に役割を限定するとUXが崩れない。
- **Nova Sonic が日本語非対応だった件の整理**：だからこそ単一の音声対音声ではなく、STT → LLM → TTS のカスケードが正解。このデモ構成はその結論の実装。

- フルカリキュラム（複数業種・全レベル）

- オフライン対応、話者認証（なりすまし防止）
- 自動コンテンツ生成パイプライン（教材の量産）

## 8. 工数感・次の一手

既存の足場（Airaの管理ダッシュボード、歯科エージェントの音声処理）に、モバイルWeb録音ページとメール送信（SES/SendGrid）を足す形。WhatsApp/通話/WABA審査が無いぶん、立ち上げは速い。コアの音声ループ（録音 → 採点 → 画面表示）を先に立て、ダッシュボードはモックから始めるのが速い。

**次の一手の選択肢（どれでも書き出せます）**
1. **AI会話プロンプト＋ルーブリックのJSON仕様**（利用者役の人格、採点基準、出力スキーマ）
2. **モバイルWeb録音ページ**（MediaRecorderで録音 → POST → 画面に即時スコア表示）。デモの入口。
3. **Azure Speech（ja-JP）発音評価のサンプルコード**（ブラウザ録音のWebM/OpusをffmpegでWAV化 → ファイル採点に通す部分）
4. **教師ダッシュボードのモックUI**（学習者ビュー＋コホートビュー）＋結果メールのテンプレート
